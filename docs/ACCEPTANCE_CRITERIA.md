# Starlume AI 辅助创作主线验收标准

## 1. 完成定义

只有以下各项在同一提交和部署版本上成立，新的辅助创作主线才可标记“已验收”：

1. 注册、登录、退出和 Token 失效行为正确。
2. 作者从灵感建立最小创作圣经，所有正式设定经过人工确认。
3. 编辑器能展示当前剧情、场景、人物、故事线、伏笔和来源。
4. 至少一个AI角色通过真实 Provider 完成持久化会话并返回可追溯候选。
5. AI候选支持局部采用、拒绝、撤销；AI失败或放弃不改变原文。
6. 候选绑定正文修订；正文变化后旧候选不能直接应用。
7. 编辑保存、AI应用和版本恢复刷新后仍正确，正式正文仍以 `contents` 为唯一真相源。
8. 人工确认章节后，连续性、人物状态、时间线、物品和伏笔能够更新并追溯。
9. 创作账本能区分人工输入、删除、粘贴、AI初始采用、撤销、采用后人工修改、有效时长和净增。
10. Provider、网络、Worker或账本失败不会显示假成功，也不会覆盖正文。
11. 三章验收使用无历史章节和V7故事状态的隔离副本；单章通过后再连续三章。
12. 三章由两位独立评审完成可读性、推进、连续性、人物、情绪/爽点和继续阅读意愿盲评。
13. 外部检测结果只有在真实报告和正文哈希一致时才展示，不冒充内部质量分。
14. 平台定稿包、AI披露人工确认、七道门禁和真实发布回执形成闭环。
15. 单元测试、构建、数据库集成、浏览器E2E、真实Provider、真实性门禁、CI和生产 smoke 按变更风险通过。

## 2. 必跑门禁

```bash
git diff --check
python3 scripts/verify_ai_truthfulness.py
python3 scripts/verify_delivery_claims.py
bash scripts/ai_development_gate.sh
```

涉及前端时：

```bash
cd frontend
npm test
npm run build
npm run test:e2e
```

涉及后端时：

```bash
cd backend
.venv/bin/pytest -q <相关测试>
.venv/bin/pytest -q
```

有真实Key时必须额外执行受控真实Provider用例；跳过不能替代：

```bash
cd frontend
npx playwright test e2e/main-chain.spec.ts --grep "protected"
```

## 3. 浏览器验收路径

1. 登录并选择测试小说。
2. 打开创作圣经，生成候选、拒绝一次、确认一项正式事实。
3. 进入编辑器，核对当前场景、人物、故事线和来源。
4. 与AI对话生成选区候选，验证实际Provider、模型和修订信息。
5. 分别执行局部采用、拒绝和撤销；刷新确认正文和版本一致。
6. 在AI请求期间修改正文，确认返回候选被标记为过期。
7. 断开Provider或使用无效配置，确认明确失败且原文不变。
8. 查看创作报告，核对人工、粘贴、AI采用、撤销和净增。
9. 确认章节并检查连续性、人物和伏笔状态更新。
10. 生成平台定稿包，完成披露确认、门禁和人工回执登记。
11. 在桌面、平板和手机宽度复验关键操作。

## 4. 状态判定

- 未开始：只有需求或没有有效产品实现。
- 已接线：存在部分入口和调用链，但缺真实用户闭环。
- 可用：正式入口、权限、持久化、错误和相关本地/E2E通过。
- 已验收：真实Provider、人工盲评、生产和真实平台证据按能力完成。

禁止使用“基本完成、核心完成、应该可用、已预留”等模糊口径。现有旧自动生成主线的历史验收不能自动升级为本文件的新辅助创作主线验收。
