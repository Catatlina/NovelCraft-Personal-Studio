# Starlume AI 小说主线验收标准

## 1. 完成定义

只有以下各项在同一提交或部署版本上成立，小说主线才可标记“已验收”：

1. 注册、登录、退出和 Token 失效行为正确。
2. 七个小说页面均可在桌面和手机访问，无非小说入口泄漏。
3. 创意输入通过真实 Provider 生成策划，失败明确失败。
4. 工作流在人工定名节点停下，未经用户确认不得继续。
5. 确认后完成首章、审阅、一致性和连续性节点。
6. 书籍和章节进入真实书库，刷新及服务重启后仍存在。
7. 编辑保存产生真实持久化；AI 编辑必须先预览。
8. 放弃 AI 编辑不改变原文；应用后可恢复旧版本。
9. 审阅只显示真实节点证据，无证据时显示空态而非默认分。
10. TXT/MD 导出的正文与数据库章节一致。
11. Provider、网络或 Worker 失败不会显示假成功，也不会留下不可解释的部分数据。
12. 单元测试、构建、确定性 E2E、真实 Provider E2E、真实性门禁和 CI 全绿。
13. 当前提交已部署，生产健康检查和关键浏览器 smoke 通过。

## 2. 必跑门禁

```bash
git diff --check

cd frontend
npm test
npm run build
npm run test:e2e

cd ..
bash scripts/ai_development_gate.sh
```

有真实 Key 时必须额外执行 protected 用例；不得用无 Key 的 `1 skipped` 结果替代：

```bash
cd frontend
npx playwright test e2e/main-chain.spec.ts --grep "protected"
```

后端发生任何改动时还必须运行受影响测试和全量：

```bash
cd backend
.venv/bin/pytest -q
```

## 3. 浏览器验收路径

1. 新用户注册并进入小说首页。
2. 创建小说，填写创意、题材、风格和篇幅。
3. 等待人工定名，检查候选标题来自真实调用。
4. 选择标题，等待节点全部完成。
5. 在书库打开详情，检查简介、目录、章节和状态。
6. 进入编辑器，修改正文并保存，刷新确认持久化。
7. 分别执行润色、续写、整章重写：
   - 结果先进入预览；
   - 放弃时原文不变；
   - 应用时写入版本；
   - 恢复版本后刷新仍正确。
8. 打开审阅页，核对评分、问题、优势、连续性、时间线和人物弧线均有后端证据。
9. 导出 TXT/MD，核对实际正文。
10. 在 390px 宽度复验七页面和关键操作。

## 4. 状态判定

- 未开始：没有有效产品实现。
- 已接线：前后端调用关系存在，但缺少真实闭环证据。
- 可用：确定性真库链路和错误路径通过。
- 已验收：真实 Provider/生产环境按本文件完成闭环。

禁止使用“基本完成、核心完成、应该可用、已预留”等模糊口径。
