# Starlume AI 产品需求规格说明书

> 版本：1.0
> 状态：现行产品契约
> 核心定位：人工主导、多AI协作、全过程可追溯的中文长篇小说创作工作台

## 1. 产品目标

Starlume AI 不再把“自动生成整本小说”作为默认交付。产品应帮助作者完成：

1. 把一句灵感发展为可持续写作的故事工程；
2. 在编辑过程中随时看见当前剧情、人物、故事线、伏笔和连续性状态；
3. 让 GPT、豆包、DeepSeek 等模型承担不同辅助角色，而不是互相重复生成；
4. 所有AI内容先成为候选，由作者选择、局部采用、改写或拒绝；
5. 保留真实人工创作记录、AI贡献和版本演化；
6. 在自然、可读、连续和平台合规的前提下完成章节发布。

北极星指标不是“AI一次生成多少字”，而是：

- 作者完成一章所需的有效创作时间；
- 候选建议被部分采用并经人工确认的比例；
- 章节返工次数和连续性错误率；
- 三章连续阅读完成率与人工盲评分；
- 最终正文的人工作者决策覆盖率和可追溯率。

## 2. 非目标

- 不承诺任何模型或任何章节稳定达到第三方检测器固定分数。
- 不用模拟键盘、伪造在线时长或伪造人工码字记录规避平台规则。
- 不让AI自动确认设定、自动覆盖正文或绕过人工发布确认。
- 不把扫榜作品的可识别表达、人物、桥段或正文送入仿写提示词。
- 不建立第二套章节正文真相源；正式正文仍进入现有 `contents` 主链。

## 3. 用户与核心场景

### 3.1 目标用户

- 从灵感开始，需要规划长篇结构的新作者；
- 已有大纲或正文，需要连续性和伏笔管理的作者；
- 同时使用多个AI，希望统一上下文和版本的作者；
- 需要向番茄、起点等平台提交章节并保留创作证据的作者。

### 3.2 核心工作流

#### 工作流 A：灵感到创作圣经

1. 作者输入一句灵感、目标平台、题材和读者承诺。
2. 联网扫榜只提炼市场机会、题材趋势和读者预期，保存来源与时间。
3. GPT 负责故事架构候选；DeepSeek 负责结构化拆解和缺口检查；豆包负责读者视角反馈。
4. 系统并列展示候选、冲突和依据，不自动合并。
5. 作者确认后，内容才进入正式创作圣经。

#### 工作流 B：章节共创

1. 作者选择当前章节和场景目标，查看章首状态、出场人物、活跃故事线和待回收伏笔。
2. 作者可以自己写、让AI扩写、让AI提供多个方向，或针对选区请求修改。
3. AI结果进入候选区；作者可接受全部、接受片段、插入光标位置、对比或拒绝。
4. 系统记录采用后的人工作者修改，不把“曾由AI生成”永久等同于最终AI占比。
5. 作者确认章节后，系统更新章末状态、人物知识、物品位置、因果账本和伏笔。

#### 工作流 C：审核与发布

1. 确定性规则先检查缺字、状态冲突、人物知识越界、时间线、重复和格式。
2. 独立AI审阅提供有正文证据的问题，不重写全文。
3. 作者决定是否修改并确认正式版本。
4. 生成平台定稿包，作者在官方工作台完成最后校改和发布。
5. 保存导出版本、平台版本、披露确认和发布回执；没有回执不得标记已发布。

## 4. 小说创作对象模型

### 4.1 作品定位

- 作品灵感与一句话卖点；
- 目标平台、频道、题材、子题材和目标读者；
- 核心情绪、读者承诺、差异化卖点；
- 预计总字数、章节字数区间、更新节奏；
- 禁写边界、版权与敏感内容边界。

### 4.2 故事发动机

- 主角长期目标、当前目标、缺陷与代价；
- 核心冲突、对抗力量、失败后果；
- 金手指的来源、能力、限制、升级方式、使用成本和反制手段；
- 持续产出剧情的循环：机会 → 选择 → 行动 → 结果 → 代价 → 新压力；
- 每阶段对读者承诺的兑现方式。

### 4.3 世界与背景事件

- 世界规则、地理、组织、权力、经济、技术或修炼体系；
- 故事开始前的重要背景事件；
- 公共时间线与隐藏时间线；
- 信息公开范围以及不同角色知道什么。

### 4.4 角色卡

所有角色均支持姓名、性别、年龄、身份、性格、外貌、欲望、恐惧、能力、弱点、人物简介、人物关系、语言习惯、行为习惯、秘密、知识范围和当前状态。

- 主角和核心反派在开篇前建立完整卡。
- 首卷关键配角先建立最小卡，只填写当前剧情真正需要的内容。
- 普通配角随剧情新增，不能为了“设定完整”一次性生成大量闲置角色。
- 配角连续出现、承担转折、掌握关键资源或建立稳定关系后，由系统建议“晋升核心角色”，必须由作者确认。
- 角色死亡、失踪、背叛、关系变化和能力变化都进入版本化状态，不能直接覆盖历史。

### 4.5 关系与故事线

- 角色关系包含方向、强度、公开认知、真实状态、变化原因和生效章节。
- 故事线分为主线、支线、感情线、成长线、对抗线、秘密线和伏笔线。
- 每条线记录目标、阶段、当前压力、最近推进、下一可能推进、依赖和长期未推进告警。
- 章节可以推进多条线，但不得为了指标机械平均分配。

### 4.6 多级大纲

- 全书方向：只固定长期承诺和不可变事实；
- 分卷大纲：阶段目标、主要对手、核心兑现和卷末状态；
- 章节细纲：章首状态、场景、冲突、结果、代价和章末钩子；
- 场景卡：视角、地点、时间、出场人物、现场目标、阻碍、信息变化和交接状态。

大纲是可版本化的导航，不是不可修改的剧本。作者调整正式设定时，系统先展示对后续章节、伏笔和角色线的影响范围。

## 5. 编辑器体验

### 5.1 三栏结构

- 左栏：章节树、卷结构、故事线、伏笔和资料导航；
- 中栏：正文编辑器、选区操作、版本对比、候选差异和保存状态；
- 右栏：实时AI对话、当前场景、出场人物、连续性提醒和建议队列。

### 5.2 作者在编辑时必须看见

- 当前章节要推进的剧情和不能改变的事实；
- 当前场景目标、冲突、预期结果和字数节拍提示；
- 出场角色的当前状态、彼此关系、知识范围和语言样本；
- 正在推进及长期未推进的故事线；
- 到期伏笔、物品去向、时间和地点冲突；
- 建议来源、模型、使用的上下文和是否会修改正式事实。

### 5.3 操作规则

- `Cmd/Ctrl+K` 打开统一命令入口；
- 选中文本后可请求扩写、压缩、换角度、对白、动作或局部修复；
- AI不得在没有确认的情况下修改正文；
- 建议必须支持局部接受和撤销，不强迫接受整段；
- 专注模式只保留正文、当前场景和阻断级提醒；
- AI回答事实问题时必须引用创作圣经、章节或状态记录来源。

## 6. 多AI分工

模型名称必须由后台路由配置，不把供应商写死在业务代码中。默认职责如下：

| 角色 | 默认模型方向 | 主要职责 | 禁止事项 |
|---|---|---|---|
| 总编/架构师 | GPT 系列 | 作品定位、结构方案、跨卷影响分析、复杂决策比较 | 不直接写入正式设定 |
| 扩写/结构执行 | DeepSeek | 场景扩写、结构化账本、长上下文检查、批量整理 | 不替作者总结主题，不自动覆盖正文 |
| 对白/读者模拟 | 豆包 | 对白候选、生活现场、角色声音、读者即时反馈 | 不为“人味”机械添加口癖和无意义细节 |
| 确定性系统 | 程序规则 | 权限、版本、状态、哈希、连续性硬事实、预算、发布状态 | 不冒充语义判断或AI评分 |

模型不可用、超时、余额不足或输出不合约时必须明确失败。系统可以让作者手动选择替代模型，但不得静默换模型后仍展示原模型身份。

## 7. 创作记录与AI贡献

系统需要记录真实会话，而不是记录敏感逐键内容：

- 会话开始、结束、前后台与空闲时间；
- 人工输入、删除、粘贴和移动字数；
- AI建议生成、展示、采用、部分采用、拒绝和撤销；
- 采用后人工继续修改的范围；
- 正式版本、导出和发布动作；
- Provider、模型、Prompt版本、上下文快照和建议ID。

仪表盘至少展示：有效创作时长、人工新增、AI净保留、人工重写、粘贴、净增和版本数。详细口径见 08 号文档。

## 8. 质量与平台边界

- 质量首先在规划和生成时解决，后置审计只做证据化兜底。
- 场景字数是节拍建议，章节目标区间才是读者侧主要约束；完整场景不因少量自然波动机械重写。
- 三章真实 Provider 验证替代当前阶段的二十章长跑；每次验证使用无历史章节的隔离副本。
- 第三方检测目标可以记录为实验指标，但只有真实报告才能形成证据，内部启发式分数不得冒充外部分数。
- 即使第三方检测结果较低，也必须遵守目标平台关于AI使用和披露的实际规则。

## 9. 权限、安全与版权

- 人工确认的设定和正文优先级最高；AI候选永远不是正史。
- 项目、小说、章节、候选、导出和平台配置必须做项目归属校验。
- API Key只通过会话、CI Secret或部署环境注入，不进入正文、日志或Git。
- 扫榜只保存必要元数据、来源和抽象洞察；不得保存或提示复现受版权保护的长文本。
- 创作账本默认只保存差异摘要和哈希；原文快照按版本权限保存，不做系统级键盘监听。

## 10. 产品验收

完整产品达到“已验收”至少需要：

1. 作者从灵感建立创作圣经并人工确认；
2. 编辑器能按当前剧情和角色真实对话，AI建议可局部采用且不覆盖原文；
3. 正式设定变更有影响分析、版本和回滚；
4. 真实码字账本可以重算并解释最终贡献；
5. 真实 Provider 失败、权限失败和冲突合并均有明确结果；
6. 清空历史隔离副本完成连续三章生成/共创，人工盲评可读、连续、角色稳定；
7. 平台定稿包、披露确认和发布回执形成闭环；
8. 自动测试、浏览器E2E、真实Provider和生产门禁全部留下证据。
