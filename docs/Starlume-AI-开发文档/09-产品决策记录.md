# Starlume AI 产品决策记录

> 版本：1.0
> 作用：冻结本轮对话确认的方向；修改这些决定必须新增决策记录并说明原因

| ID | 决策 | 原因 | 影响 |
|---|---|---|---|
| ADR-001 | 产品统一命名为 Starlume AI | 旧品牌已废止 | 新UI、新文档、新仓库使用新名称；旧技术标识兼容保留 |
| ADR-002 | 主产品从AI自动生成转为人工主导辅助创作 | 自动长跑无法替代作者创意、审美和最终责任 | 默认入口围绕创作圣经、编辑器和人工确认 |
| ADR-003 | 所有AI输出默认是候选 | 防止AI污染正史和覆盖原稿 | 候选、正式事实和正文分层；必须人工应用 |
| ADR-004 | GPT、DeepSeek、豆包按角色协作 | 不同模型能力和成本不同 | 角色路由可配置；无真实Key不得冒充验收 |
| ADR-005 | 确定性系统只管可验证规则 | 规则稳定但不能代替语义判断 | 权限、版本、状态、哈希和硬事实用程序；创意和语义用AI/人工 |
| ADR-006 | 生成时优先解决自然、可读、连续 | 后置全文重写会破坏低风险文本和事实 | 审计只定位问题，局部修复是兜底 |
| ADR-007 | 章节目标区间是主要字数约束，场景预算是软节拍 | 读者接受度和场景完整性高于机械均分 | 少量场景波动不触发全文重写；章节总预算保留硬边界 |
| ADR-008 | 当前只做三章真实验收，不做二十章长跑 | 降低成本并提高根因诊断效率 | 单章通过后才跑三章；失败即停，不盲重试 |
| ADR-009 | 所有长跑使用无历史章节的隔离副本 | 防止旧状态污染和覆盖原作 | `active_chapters=0` 与无V7故事状态为启动前置门禁 |
| ADR-010 | 95/5/0是外部实验目标，不是内部可自证结果 | 检测器会变化且内部启发式不等同外部报告 | 只有真实报告可记录；不免除披露和平台合规 |
| ADR-011 | 码字记录必须真实，不做键盘模拟 | 伪造记录有平台、账号和诚信风险 | 建立会话/事件账本；平台活动由作者在官方工作台真实完成 |
| ADR-012 | 配角按剧情动态新增和晋升 | 一次性创建大量配角增加负担且易僵化 | 主角/核心反派先完整，关键配角最小卡，普通配角按需新增 |
| ADR-013 | 编辑器采用左导航、中正文、右AI协作 | 作者需要边写边看剧情和角色 | 上下文卡、角色卡、故事线和AI会话在同一工作台 |
| ADR-014 | 先复用现有能力，再做最小新增 | 当前系统已经有大量可复用链路且流程过于复杂 | 禁止另建正文、Gateway和审阅平行系统；按垂直切片开发 |
| ADR-015 | 现有 `Catatlina/starlume-ai` 不覆盖 | 该名称已属于另一历史项目 | 当前主仓库使用 `Catatlina/starlume-ai-studio` |
| ADR-016 | 创作控制面只新增五张最小表，正文继续复用现有主链 | 当前系统已经有 contents、versions、ai_calls、knowledge_items、model_routes 和 publication 数据；另建正文/Provider真相源会增加冗余和审计风险 | `nc_starlume_authoring` 只保存会话、消息、事件、长跑登记和人工回执；M7/M8仍需真实验收 |
| ADR-017 | 生成期开场门禁允许短环境引子后的早期动作 | 真实 Provider 暴露出“首句环境、前160字内已发生可见动作”的自然开场被硬规则误判；继续调用前缀修复 Provider 反而增加失败面 | 仅放行首句未分类且前160字出现动作的有限情况；动作过晚、静态环境、身体模板仍阻断并保留证据 |
| ADR-018 | 架空题材非露骨冲突词默认只告警 | 玄幻真实样本中的“杀人”属于剧情语境，旧全局敏感词硬门禁误伤正常正文；安全类别与题材冲突必须分层 | 记录命中并提示人工复核；政治、色情、毒品、赌博、自残、现实违法和露骨/极端暴力仍硬阻断；项目可关闭 `allow_fictional_violence` |
| ADR-019 | 章节总预算是唯一读者硬上限 | 真实 Provider 暴露出场景目标预算被误当第二硬上限，阻断了章节总量仍有空间的完整场景；用户明确要求按每章可读预算控制 | 场景/读者目标只作规划告警；章节总预算与后续场景最低表达空间继续硬阻断 |
| ADR-020 | 最后完整场景允许 480 字有界自然波动 | 真实 Provider 在无后续场景时产出完整收束候选，但仅因前场超出分配导致 353 字预算差被阻断；硬切/后置整章重写都会损害事件闭合和可读性 | 仅无后续场景、候选完整且其他门禁通过时生效；不增加推荐目标、不允许补写，超出 480 字仍阻断 |
| ADR-021 | 跨场景段首风险必须由当前候选自身重复触发 | 真实第二章第3场只有一次自然交接段落，却因前面场景已有主角段首比例而触发交叉误报；继续重写会把连续性问题误当成语言问题 | 只有候选自身重复同一姓名段首至少3段且占比至少45%才触发交叉重试；候选自身强重复和整章后置审计仍保留 |

## 修改流程

修改任何已接受决策时必须：

1. 新增 ADR，不能原地删除历史决定；
2. 写出触发证据、备选方案、成本和回滚；
3. 更新 PRD、架构、开发路径、需求矩阵和交接；
4. 如果涉及外部写入、数据迁移或发布，取得用户明确授权；
5. 在真实门禁前不得把新方向写成已验收。
