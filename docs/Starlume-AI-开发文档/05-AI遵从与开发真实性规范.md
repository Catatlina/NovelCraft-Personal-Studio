# Starlume AI AI遵从与开发真实性规范

> 版本：2.0
> 状态：强制执行
> 适用对象：产品内AI、编码Agent、自动化工具和人工开发者

## 2026-08-20 实施状态补充

当前实现把“是否真实调用”与“是否允许写入”分开：`ai_calls` 能关联到会话候选时才标记 Provider 已验证；客户端单独提交的 assistant 消息会标记为未验证。角色面板显示的是环境密钥和实现状态，不是质量承诺。清空长跑接口需要显式 `confirm_clean=true`，并且只软删除活动章节、保留版本。

## 1. 两类遵从

### 1.1 产品AI遵从作者

产品AI必须：

- 把作者目标、正式设定和正式正文作为最高事实；
- 只在授权范围生成候选；
- 明确展示使用的角色、模型、上下文和修订；
- 不知道时说明缺失，不补写为正式事实；
- 发现冲突时并列展示，不擅自替作者选择；
- Provider失败、超时、截断或账本失败时明确失败；
- 未经人工确认不修改正文、设定、发布状态和披露状态。

产品AI不得：

- 把模型记忆或联网材料覆盖到正史；
- 用固定模板、关键词、启发式或旧缓存冒充真实AI结果；
- 静默切换Provider或模型；
- 在Writer提示中加入规避第三方检测器的目标；
- 自动应用整章重写；
- 伪造人工编辑、平台码字、检测报告或发布回执。

### 1.2 开发AI遵从仓库事实

开发AI必须把用户请求、当前代码、运行结果和外部回执作为裁决依据。文档、历史聊天和旧报告只提供线索，不能覆盖当前证据。

每次工作前必须读取：

1. `AGENTS.md`；
2. 本文件；
3. `docs/AI_HANDOFF.md`；
4. `docs/REQUIREMENTS_TRACEABILITY.md`；
5. `docs/KNOWN_ISSUES.md`；
6. `docs/ACCEPTANCE_CRITERIA.md`；
7. 当前任务文档（默认 `03-开发路径与里程碑.md`）；
8. 用户提供的最新报告。

## 2. 最小化与复用

开发前必须盘点现有入口、服务、模型、表、事件、测试和依赖。可以扩展现有能力时不得创建平行实现。

新增抽象、依赖、表或服务前必须记录：

- 现有能力为什么不能满足；
- 新增边界、失败语义和退出方案；
- 对维护、迁移、供应链和运行成本的影响；
- 最小垂直切片如何验证。

目标架构不是一次性建设清单。只实现当前用户闭环需要的最小部分。

## 3. 状态口径

对外只允许：

| 状态 | 定义 |
|---|---|
| 未开始 | 没有可执行实现，或只有需求/设计 |
| 已接线 | 存在部分入口和调用链，但缺完整用户结果或真实验收 |
| 可用 | 正式入口可运行，失败明确，相关本地/集成门禁通过 |
| 已验收 | 同一提交/部署具有所需真实Provider、浏览器、生产或平台证据 |

禁止“基本完成、核心完成、应该可用、代码级完成、完成了大部分”等模糊口径。

## 4. AI能力完成条件

AI能力标记“可用”或“已验收”前必须满足：

1. 正式用户/API/Worker入口；
2. 真实 Gateway/Provider 路径；
3. `ai_calls`或等价溯源；
4. 项目权限、状态、幂等和持久化闭环；
5. Provider/格式/预算/账本失败明确失败；
6. 成功、失败、权限、持久化和冲突测试；
7. 用户主链有浏览器E2E；
8. 声称真实模型效果时有真实调用证据。

Monkeypatch可验证协议、权限、回滚和失败路径，不能证明真实模型质量。

## 5. 外部依赖

需要AI Key、平台账号、Cookie、API、TLS、外部数据源、检测器或发布回执的能力，在未真实执行前最高只能标记“已接线”。

真实外部验证必须记录时间、版本、目标、输入哈希、响应/回执和失败边界。不得在Git、Prompt、日志或交接文档写入密码、Token或完整密钥。

## 6. 开发顺序

1. 建立任务契约：目标、入口、范围、非目标、约束和验收；
2. 检查工作树和最新远端，保护用户改动；
3. 读取入口、数据流、状态流、失败流和测试；
4. 写复用清单和最小新增清单；
5. 实现一个垂直切片；
6. 运行最便宜且相关的检查；
7. 根据证据修正，不围绕猜测连续尝试；
8. 扩大测试到集成、E2E、真实Provider/平台；
9. 审查差异、秘密、无关改动和回滚点；
10. 更新交接、需求追踪和已知问题；
11. 仅在用户授权后提交、推送、开PR或部署。

## 7. 强制门禁

每次交付至少运行：

```bash
git diff --check
python3 scripts/verify_ai_truthfulness.py
python3 scripts/verify_delivery_claims.py
bash scripts/ai_development_gate.sh
```

UI改动增加前端测试、类型/构建和相关浏览器E2E；后端改动增加定向测试和全量基线；迁移增加升级、降级/恢复和备份验证；真实AI或平台能力增加真实外部验收。

无法运行时必须记录未运行项、阻断原因、替代检查和剩余风险。

## 8. 禁止的假完成

- 文件、组件、路由、表或函数存在即宣称完成；
- Mock、固定JSON、静态模板、启发式或 degraded 结果包装为成功；
- 没有活跃调用者的 helper/deprecated 模块写成已融合；
- 测试跳过、零用例或 monkeypatch 结果写成真实AI通过；
- HTTP 200、路由401或页面能打开写成业务闭环通过；
- 内部评分写成朱雀等外部检测结果；
- 没有账号和回执写成平台发布完成；
- 没有清空历史副本就开始长跑；
- Provider失败后反复调用而不形成根因假设。
