# 通用写作系统（v1.0）

本系统把写作规则分为三层，避免一个项目的设定或样本污染其他小说：

1. **通用层**：事实卡、事件单元、五列因果账本、知情边界、物件/时间/资源追踪、模型适配记录和外部回归记录。
2. **品类层**：由真实 `genre_id` 解析品类包，负责番茄爽文节奏、章节标题、爽点密度、读者承诺、禁写规则等品类行为。
3. **项目层**：当前小说自己的设定、人物状态、黄金样本和负样本，只能按当前 `project_id` 进入上下文。

## 统一工作流

`事实卡 → 场景计划 → 正文生成 → 事件因果审查 → 受影响事件单元重写 → 质量门禁 → 外部回归`

每个章节生成前必须具备：

- 已确认事实和人物知情边界；
- 当前时间、地点、物件、资源和关系状态，未知项保留未知；
- 核心问题、可见兑现、代价/余波、下一压力；
- 每个关键事件的“事件 / 谁知道 / 为什么现在 / 代价 / 下一影响”；
- 当前项目可用的行为样本（如果项目导入了样本）。

模型、版本、提示词版本、温度、输出上限和样本数量会写入 `model_adaptation`，用于后续校准和回归，不能只看最终分数判断某次改动是否有效。

缺少事实卡或因果账本时，在调用正文模型前停止，不生成一篇事后才发现无法追溯的正文。

## 样本规则

黄金样本只保存行为标注，不把原文当作可复制素材。检索只返回当前项目最多 2—3 个样本，模型只能学习：人物目标、信息缺口、选择压力、因果推进、可见结果和结果成本；禁止复制原句、句长、标点、段落结构和专有名词。

项目样本导入字段见 `docs/BEHAVIOR_SAMPLE_IMPORT_SCHEMA.md`。大唐样本放在项目空间，不进入全局规则，也不会自动出现在封神或其他题材的上下文。

## 审查颜色

- **红色**：逆因果、知情越界、物件瞬移、规则冲突；必须返回场景或返回骨架。
- **橙色**：巧合救场、工具人、无代价成功、外部钩子硬接；进入修复边界。
- **黄色**：解释腔、完美问答、主角中心化；作为表达和读者体验风险处理。

重写边界以事件单元为单位：`刺激 → 选择 → 可见结果`。未受影响的事实、物件、结果和未决问题必须保留。

## 外部检测

朱雀等外部报告只能通过正文 SHA-256 绑定后登记，系统不推测、不伪造外部“人工率”或“AI率”。外部检测是最后一道证据门，不替代生成前的事实设计、品类节奏和可读性控制。

## 来源合并边界

- `通用写作方法论/` 与 `通用写作方法论-v1.0.0.zip` 内容重复，只保留目录作为阅读源，zip 作为归档，不重复注入。
- `写作系统/` 中的通用协议已抽取进本文件和机器契约；其中包含《大唐：我的后台是整个华夏》专属角色、国家端/唐端语义的部分只作为项目样本来源，不进入全局 Prompt。
- 真实品类规则继续由 `genre_id` 加载；项目事实优先于通用建议，品类规则不能改写项目硬设定。
