# 生成质量整改与 V6/V7 最终验收执行说明

## 结论先行

本轮已经把“发现风险”和“允许通过”接成同一条闭环：

- V7 是唯一正文生成链；V6 负责内容库、编辑器、版本和导出承载。
- 节奏/铺垫、因果逻辑、跨章连贯、伏笔推进和 AI 腔的中高风险会阻断通过。
- 失败稿仍会保存并展示问题，状态为 `needs_rewrite`，不会再显示成“已完成”。
- 编辑器的“按全部建议润色”“按全部建议改写”“整章重写”继续采用预览→人工确认→应用→自动保存→版本可回滚。

这意味着“去掉风险”不是把风险文字从页面上删掉，而是把风险对应的正文问题修掉，重新审阅通过后风险自然消失；未修好时必须继续显示。

## 1. 20 章双轨人工盲评

执行脚本：

```bash
scripts/v6v7_20_chapter_quality.py --execute \
  --confirm I_UNDERSTAND_REAL_API_COST_AND_DUAL_WRITE \
  --old-project-id <v6-project> --old-novel-id <v6-novel> \
  --new-project-id <v7-project> --new-novel-id <v7-novel> \
  --score-file <output>/blind-scores.csv
```

脚本会生成：

- `blind-review-packet.json`：匿名的 A/B 章节样本；
- `blind-review-private-map.json`：只由验收负责人保管的 A/B 对照表；
- `blind-scores.template.csv`：两位评审共同填写的评分表；
- `blind-review-instructions.md`：评审规则。

必须满足：20 个 case 全部完成、每个 case 有两位不同 `reviewer_id`，且新链路人工平均分达到 continuity ≥85、voice ≥80、fact_safety ≥85、overall ≥85；AI 腔分数按“越低越好”，新链路不能劣于旧链路。只有这些条件同时满足，脚本才会输出 `accepted`。

同一个人填两行、用同一个账号代替两位评审、或让模型自动生成评审分数，都不能作为人工盲评证据。

## 2. 跨章连贯与去 AI 腔

每章现在按以下顺序处理：

```text
生成 → 七维审阅 → 风险分类 → 定向重写 → 再审阅 → 通过后写入 V6
                                  └─仍失败：needs_rewrite，不标记完成
```

定向整改规则：

- 节奏/铺垫：补“可见动作/线索 → 场景目标 → 阻碍 → 选择 → 结果”，高潮之后保留具体余波；
- 逻辑：补齐“触发 → 人物知道什么 → 选择依据 → 代价 → 结果”，不允许靠旁白一句话硬解释；
- 跨章：必须接上一章的具体地点、人物状态、物品和未解悬念；新人物、地点、能力和规则要先有迹象；
- AI 腔：打散同构句和段长，删模板套话、公文连接词、总结体，用动作、对白和人物口吻承载情绪；
- 伏笔：到期伏笔要推进或回收，不能只在审阅意见里“标记已知”。

代码层还会把问题落成 `quality_repair_contract`，记录所需修复类别、目标和验收条件，供下一次重写使用。

## 3. V6/V7 产品合并最终人工验收

在同一生产账号上完成以下链路并留证：

1. V7 生成一章，确认 V7 run、`transition_contract`、质量门结果存在；
2. V6 书库中出现同一章节且 `generation_key` 幂等，不产生重复章节；
3. 编辑器打开该章节，执行一次预览、应用和刷新，确认新正文持久化；
4. 版本历史出现 AI 分支和自动保存版本，能够回滚；
5. TXT、Markdown、EPUB 导出内容与编辑器正文一致；
6. 质量失败时书库/进度页显示 `needs_rewrite` 或“质量待处理”，不能显示绿色完成；
7. 两位盲评人签字确认 20 章结果，产品负责人确认生成、编辑、导出和状态语义。
