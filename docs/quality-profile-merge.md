# 网文质量策略合并说明

## 结论

本项目不把多个作者包、平台包或 Skill 直接拼接进 Prompt，也不运行两套正文生成器。它们被整理成一个版本化质量策略，由 V7 作为唯一正文运行时；V6 只负责兼容既有书库、编辑器、进度和导出。

当前默认策略是“番茄式高留存 + 都市通用”，项目元数据可以切换到起点、玄幻、仙侠、都市神豪、凡人流、传统升级等组合。

新建小说页已提供“目标平台”和“细分流派”两个可选项；不选择细分流派时由题材自动匹配，旧客户端不传字段时继续使用番茄式高留存默认策略。

## 已合并的来源与取舍

- 都市通用质量包：现实摩擦、人物锚点、行业/资金/关系账本、对白潜台词。
- 都市神豪质量包：开局落差、可量化能力约束、现金流与风险、对手反应、章内小闭环。
- 玄幻仙侠质量包与天蚕土豆写作质量包：量化境界、公开反馈、升级契机/代价/验证、设定使用而非说明、升级与小高潮递进。
- 番茄/起点适配包：平台规则作为软策略，不把易变的字数或爽点频率写成不可变硬阈值；书名、简介、章名和开篇按平台选择。
- `urban-novel-writing-master`、`xianxia-xuanhuan-writing-master`、`novel-platform-style-master`：只提取方法和检查维度，不把 Skill 原文、作者姓名、原句或风格模仿指令注入运行时。
- 两份 20 章质量评审：保留“账本自洽、具体感官、人物标志动作、去模板动作”的正向证据，并补上“爽点偏沉时提高局部反馈、控制比喻疲劳”的策略。

## 运行时链路

```text
项目元数据
  → QualityProfile（平台 × 主类型 × 细分类型）
  → 规划/细纲生成 payoff_contract
  → V7 Scene Director 生成正文
  → 确定性去 AI 味 + 精确重复段落修复
  → 33 维审计 + 连续性/真相状态校验
  → 通过才写入 V6 contents 与 Novel Brain
```

### 章节爽点契约

爽点不是“每章打脸”，而是本章必须让读者看到：

`读者承诺 → 当前压力 → 主角主动选择 → 可见结果 → 代价/余波 → 下一压力`

兑现类型可以是突破、打脸、资源、揭示、关系变化、逃生、规则利用等。契约没有固定字数要求，但新 V7 章节必须有可验证字段；审稿器还必须从正文中摘取可定位的证据。

### 连续性与真相

Novel Brain 仍是唯一真相源。章节状态、人物、世界观、因果、伏笔、时间线、资源和关系由现有状态引擎保存；本次只在交接契约中增加爽点结果与证据，不新建平行真相库。每章通过后才沉淀状态，失败稿不能成为下一章上下文。

### 去 AI 味

- 不禁止单个词或单个标点。破折号、省略号、分号是否异常取决于整章密度、连续重复和语境。
- 统计套话、同构句、动作 tic、句长均匀度、段落开头重复和完整段落重复。
- 仅对“完整相同且达到安全长度”的段落做确定性去重，保留第一份并记录证据；短对白和有意回环不删除。
- 语义改写必须通过原文长度/段落保留门禁；扩大成 `2826 → 5537` 等候选直接拒绝，不能显示已完成。

### 质量门禁

现有 33 维审计继续保留。连续性、人物声音、逻辑、节奏、文字质量和约束遵守是硬门；读者体验用于指导返工，不替代硬门。章节契约和正文证据只在新质量策略生效时强制，旧 V6 历史可读、可回放、可继续生成。
