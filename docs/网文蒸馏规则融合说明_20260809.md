## 规则边界

### 进入生成契约的规则

- 系统奖励或能力收益必须改变选择，并产生使用、验证、消耗或风险
- 悬疑反转必须能回溯到前文线索，禁止“突然想到式”推理
- 历史制度、官职、称谓和物件必须服从本书历史账本
- 玄幻突破、越级和法宝变化必须有依据、代价和验证
- 科幻资源、科技和进化必须有来源、限制或失败风险
- 游戏数值、装备和技能必须改变战术选择
- 洪荒封神的因果、生死、法宝和量劫时间线必须服从本书世界观

这些规则会进入 V7 quality_profile、chapter_rules 和 Writer 指令，并通过现有爽点契约、连续性事实和质量链继续处理。

### 只作为软审计的规则

章节字数、段落长度、短段率、句长、感官锚点和长段连续次数均记录到 report_metrics。它们是样本基线，不是发布门禁，避免把平台统计中位数误当成所有好稿的硬条件。

### 明确排除

- R 段原文和标题样本
- 网站域名广告、水印和采集污染
- 具体作品或作者的仿写
- 未提供清洗过程和置信度的粗口统计

## 规则优先级

1. 本书事实账本、作者明确设定和章节连续性
2. 当前章节功能与爽点契约
3. 品类机制规则
4. 平台写作基线
5. 统计软指标

因此，报告中的境界、货币、官职、资源数量和时间线都不能覆盖当前小说已经确认的事实。
